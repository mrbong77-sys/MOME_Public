# Supplementary S1 — the MOME safety score, in full

Generated by `paper/tools/export_score_card.py` from the frozen coefficient
files; nothing here is typed by hand. Every value below is what the gate
actually evaluates.

## What is fitted, and on what

At inference the gate reads no gold answer and no grader: `c_safe` is a
function of the model's own outputs alone. The coefficients below were
fitted **offline, on correctness labels**. Two predictors exist and they are
not interchangeable.

| | fitted on | calibration layer | used for |
|---|---|---|---|
| `s_v1.json` | all 4497 items | Platt (a = 5.2230, b = -2.5449) | deployment |
| `s_v1_backbone_out.json` | the other four backbones | none — read raw | every number in the paper |

The thresholds were selected on the uncalibrated backbone-out scale.
Applying the Platt layer that the thresholds were not chosen under moves the
bands (measured: serve 31.8% to 17.2%), which is why `gate.c_safe` returns the
raw logistic output when the two Platt keys are absent.

## Scoring rule

```
z = intercept + Σ_i coef_i · (x_i − mean_i) / scale_i
c_safe = 1 / (1 + exp(−z))                     # backbone-out predictors
c_safe = 1 / (1 + exp(−(a·raw + b)))           # shipped predictor only
```

A feature that is absent for an item — no MUST_CHANGE probe survived the
well-posedness filter, for instance — enters as `0.0` **before**
standardization, so it is carried at its standardized distance from the
training mean rather than imputed. `n_probes`, `flip_n`, `scale_n` and
`hold_n` record how many probes the item actually had, so the absence is
itself visible to the score.

## Features that coincide

Twenty-six is the number of fields the fingerprint writes, not the number of
independent quantities it carries. Two groups are identical columns in the
training matrix, and the logistic therefore splits one weight among them:

- `hold_instability`, `hold_violation_any`, `hold_violation_frac` — every item carries exactly one MUST_HOLD probe, so the rate, the fraction and the indicator are the same column
- `nc_truncated`, `orig_truncated` — the two took the same value on every item in these runs (234 truncated, 4263 not), so they enter as one column

Read the coefficients accordingly: the contribution of the MUST_HOLD
violation is the sum over its three spellings, not any one of them.
